# Videorix

Videorix — локальный кроссплатформенный веб-сервис для загрузки видео с YouTube. Вставьте ссылку, выберите доступное разрешение и сохраните результат в MP4 или MOV.

Сервис запускается одной командой через Docker Compose и рассчитан на macOS и Windows. Интерфейс доступен только на текущем компьютере. Готовые файлы можно скачивать повторно, пока они не удалены вручную или автоматически через час.

> Используйте Videorix только для материалов, которые вам разрешено скачивать и использовать. Проект не обходит DRM, платный доступ или ограничения правообладателей и не связан с YouTube или Google.

## Возможности

- выбор точного доступного разрешения;
- сохранение в MP4 или MOV без перекодирования видео;
- объединение видео и звука через FFmpeg;
- последовательная очередь из нескольких загрузок;
- повторное скачивание готового файла в течение 60 минут;
- ручное удаление отдельных файлов и общая очистка очереди;
- контроль свободного места и автоматическая очистка временных данных;
- гостевой режим и локальный вход в YouTube для случаев, когда сервис требует авторизацию;
- резервные способы получения видео через yt-dlp, Cobalt и YouTube.js;
- сохранение локальной YouTube-сессии между перезапусками.

## Требования

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) с Docker Compose v2;
- свободное место для исходных дорожек и готового файла;
- современный браузер.

Для Windows используйте Docker Desktop с Linux-контейнерами и WSL 2. Конфигурация Compose не содержит путей, завязанных на macOS; текущая версия полностью проверена на macOS, а Windows-сборка требует дополнительной ручной smoke-проверки. Node.js, Python и FFmpeg устанавливать на компьютер отдельно не требуется — они находятся внутри контейнеров.

## Быстрый запуск

### macOS

Откройте Terminal и выполните:

```bash
git clone https://github.com/oxo-foxxo/youtube-downloader.git
cd youtube-downloader
docker compose up -d --build
```

### Windows

Откройте PowerShell и выполните те же команды:

```powershell
git clone https://github.com/oxo-foxxo/youtube-downloader.git
cd youtube-downloader
docker compose up -d --build
```

Первый запуск может занять несколько минут: Docker скачает базовые образы и соберёт приложение. Когда контейнеры будут готовы, откройте:

**http://localhost:8080**

Проверить состояние можно командой:

```bash
docker compose ps
```

Все четыре сервиса должны перейти в состояние `healthy`. HTTP-проверка приложения:

```bash
curl http://localhost:8080/health
```

В PowerShell без `curl`:

```powershell
Invoke-RestMethod http://localhost:8080/health
```

## Как скачать видео

1. Откройте `http://localhost:8080`.
2. Вставьте ссылку на обычное видео YouTube или Shorts.
3. Нажмите **Проверить**.
4. Выберите разрешение и MP4 или MOV.
5. Нажмите **Скачать**.
6. Когда файл будет готов, браузер начнёт сохранение. Кнопка **Скачать ещё раз** останется доступной в очереди.

Можно добавлять новые ссылки, пока предыдущий файл готовится. Задачи выполняются по одной, чтобы несколько тяжёлых загрузок не занимали весь диск одновременно.

## Вход в YouTube

Некоторые сети и видео YouTube блокирует проверкой «Войдите, чтобы подтвердить, что вы не бот». В этом случае:

1. Нажмите **Войти в YouTube**.
2. В открывшемся окне самостоятельно войдите в Google и пройдите двухэтапную проверку, если она включена.
3. Дождитесь открытия YouTube и нажмите **Я вошёл** под окном.
4. Повторите проверку ссылки.

Videorix использует отдельный Chromium-профиль в Docker-томе `youtube-session`; профиль вашего обычного браузера не читается. Cookies YouTube копируются во временный файл только на время вызова yt-dlp и затем удаляются. Они не передаются Cobalt или YouTube.js.

Кнопка **Выйти** отменяет незавершённые задачи и удаляет сохранённый профиль YouTube. Не сохраняйте пароль в отдельном браузере Videorix.

## Хранение и очистка

- рабочие и готовые файлы находятся в Docker-томе `work-data`;
- готовый файл хранится 60 минут и доступен для повторного скачивания;
- **Удалить файл** очищает одну завершённую задачу;
- **Очистить завершённые** удаляет все завершённые файлы;
- уже сохранённый браузером файл остаётся в папке загрузок пользователя;
- прерванные задачи очищаются при перезапуске и автоматически не продолжаются;
- перед загрузкой и во время неё сервис проверяет свободное место, сохраняя резерв 1 ГиБ.

Остановить приложение, сохранив сессию и готовые файлы:

```bash
docker compose down
```

Остановить приложение и удалить сессию, очередь и все Docker-тома проекта:

```bash
docker compose down -v
```

## Обновление

```bash
git pull
docker compose pull
docker compose build --pull app session-browser
docker compose up -d
```

## Настройка порта

По умолчанию Videorix слушает только `127.0.0.1:8080`. Чтобы изменить локальный порт:

```bash
cp .env.example .env
```

В PowerShell:

```powershell
Copy-Item .env.example .env
```

Затем измените `APP_PORT` в `.env` и перезапустите Compose.

Не устанавливайте `APP_BIND_ADDRESS=0.0.0.0` и не публикуйте сервис через reverse proxy: приложение рассчитано на одного локального пользователя и не содержит собственной системы аккаунтов или HTTPS.

## Диагностика

Посмотреть состояние и последние журналы:

```bash
docker compose ps
docker compose logs --tail=200 app session-browser cobalt bgutil
```

| Проблема | Что проверить |
| --- | --- |
| Страница не открывается | Убедитесь, что Docker Desktop запущен и контейнер `app` имеет статус `healthy`. |
| Порт 8080 занят | Измените `APP_PORT` в `.env`. |
| YouTube просит подтвердить вход | Используйте локальное окно входа или попробуйте другую сеть без VPN. |
| Недостаточно места | Очистите завершённые задачи и освободите место в хранилище Docker Desktop. |
| Один из провайдеров недоступен | Проверьте `/health`; Videorix продолжит работу, если доступен другой способ загрузки. |
| После обновления возникла ошибка | Выполните `docker compose down`, затем пересоберите сервис с `docker compose up -d --build`. |

Статус `/health` подтверждает доступность компонентов, но не гарантирует, что YouTube не изменил свои внутренние механизмы или не ограничил текущее подключение.

## Ограничения

- поддерживаются одиночные опубликованные видео и Shorts;
- плейлисты и прямые трансляции не поддерживаются;
- приватные, платные, возрастные и регионально закрытые материалы могут быть недоступны;
- MOV создаётся через remux без перекодирования и не является ProRes;
- интерфейс предлагает только сочетания разрешения и контейнера, доступные без изменения кодеков;
- изменения YouTube могут временно нарушить один или несколько способов загрузки.

## Архитектура

Docker Compose запускает четыре сервиса:

- `app` — Fastify API, React-интерфейс, очередь, yt-dlp, FFmpeg и гостевой Chromium;
- `session-browser` — отдельный Chromium с noVNC для локального входа в YouTube;
- `cobalt` — резервный источник медиапотоков;
- `bgutil` — локальный поставщик PO-токенов для yt-dlp.

Порты служебных контейнеров не публикуются на хост. `app` общается с ними по изолированным Docker-сетям. Управляющий API браузера входа защищён случайным локальным токеном.

## Разработка

Для локальной разработки без сборки Docker нужны Node.js 22+ и pnpm 11:

```bash
pnpm install
pnpm run typecheck
pnpm test
pnpm run format:check
pnpm run build
```

E2E-проверки используют локальный тестовый сервер и не обращаются к YouTube:

```bash
pnpm exec playwright install chromium
pnpm run test:e2e
```

Для явной онлайн-проверки уже запущенного Docker-приложения:

```bash
pnpm run smoke:youtube -- "https://www.youtube.com/watch?v=VIDEO_ID" --height 720 --container mp4
```

Smoke-скрипт ждёт готовности, скачивает файл, проверяет разрешение и наличие видео- и аудиодорожек через FFprobe, а затем удаляет тестовую задачу.
